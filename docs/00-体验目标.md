# 代号1 体验目标（设计北极星）

> **本文件优先于一切玩法、数值、系统、商业化文档。**  
> 后续任何设计、改需求、加系统，都必须先用本文「审视清单」过一遍；通不过则改方案或砍掉，而不是改体验目标去迁就功能。

品类：单局肉鸽制的英雄编队自走防守（LD like + Roguelike + 轻背包）  
平台：微信 / 抖音小游戏　变现：首版纯 IAA；IAP 只预留结构，待版号后再开（见 §4.1）

---

## 1. 主体验目标

**正式表述**

> 当玩家在碎片时间开一局时，反复感到：**「这支队是我攒出来的，他们自己就能打赢，而且越攒越能打」**——赢来自我选了谁、把他们放在哪，而不是我手速快或者肝得久。

**一句话**

> **看戏 + 收英雄：我攒的队，自己替我打赢。**

**玩家应脱口而出**

- 「这个英雄真好用」
- 「刚才那个三选一选对了」
- 「把他挪到前排就顶住了」

---

## 2. 反目标（坚决避免）

玩家若经常感到以下任一，即体验目标失败：

| 反目标感受 | 典型诱因（设计上要挡） |
|---|---|
| **「反正它自己会打，我选谁都一样」** | 克制与站位收益被数值差抹平；三选一没有取舍 |
| 「打不过就是运气不好」 | 随机性主导结果，决策权重不足 |
| 「每回合还要手动点，累」 | 把自动战斗改回手操；观战被操作打断 |
| 「不解锁新英雄就过不去」 | 通关绑定特定英雄；广告位变成过关前置 |
| 「系统太多，不知道该干啥」 | 多养成线、多货币、局外目标冲突 |

第一条是本项目的头号风险。自动战斗天生会让玩家怀疑自己的决策无效，所有设计都要反向证明「换人换站位真的会改变结果」。

---

## 3. 体验结构（主 / 辅）

| 层级 | 内容 | 说明 |
|---|---|---|
| **主** | 收英雄 + 编队决策 | 三选一攒阵容 ↔ 波次敌人的系别与压力 |
| **强辅** | 自动战斗的观战爽感 | 让「选对了」的结果打得好看、看得懂；不抢主目标 |
| **弱辅** | 局外解锁进度 | 给「换阵容」提供弹药与覆盖面；不做成第二条养成线 |

聪明感的**关键时刻**：卡在某一波 → 下一局换阵容或调站位 → 打得更深。  
若玩家卡关后第一反应是「再来一局碰运气」而不是「换个搭配」，主目标已偏。

---

## 4. 游玩情境（设计约束）

以下每条都是硬约束，不是建议。来源是这一轮的市场与买量调研，以及 xiaochu2 的实测教训。

| 约束 | 值 | 为什么 |
|---|---|---|
| 单局长度 | 15 波，7–10 分钟 | 碎片时间可完整打完一局；短回收模型要求成长压进单局 |
| **十秒可懂** | 前 10 秒内玩家能看懂「选人 → 他们自己打」 | 直玩已是 IAA 买量第一大形态（头部渗透率 95%、点击转化率提升 3 倍）。开局不允许有编队页等前置流程，必须直接进战场 |
| **核心流程广告点 ≤ 2** | 只放「结算双倍」与「突破底线复活」 | 大盘数据：核心单流程广告点少于 3 个时新进次留约 23%，3–5 个掉到 17%。xiaochu2 现在排了 4 个，正落在差的那一档 |
| **中位数 IPU ≥ 6** | 人均日广告展示次数，看中位数不看平均 | 纯 IAA 的收入底线。xiaochu2 平均 7.9 看似达标，实际是两名重度用户抬起来的，一个活跃玩家真实值只有 0.57 |
| 不接插屏 | 切片与首版都不接 | 平台把插屏与激励视频算在同一频控窗口，而激励视频 eCPM 明显更高，接插屏等于用贵的换便宜的 |
| 克制系数量 | 3 系循环 | 5 系在 7 分钟单局里学不完，且违反十秒可懂 |
| 首版无内购 | 不开 IAP，但按 §4.1 预留结构 | 没有版号，且小游戏开内购另需资质与审核。任何「靠付费深度才能过」的设计在无版号期都无法变现，只会变成劝退 |

### 4.1 IAP 预留原则

首版纯 IAA，但**结构从第一天就要留**。理由来自 xiaochu2 的实测教训：如果免费经济先按「完全没有付费」校准过一轮，等到能开付费时再塞进去，只能靠打折扣硬挤，最后变成付费不值钱、免费也被削。

预留的成本几乎全在**口径**上，不在功能上。按下面三档执行。

| 档位 | 内容 | 为什么归在这一档 |
|---|---|---|
| **现在就必须定** | ① 所有资源发放走同一入口，带 `source` 字段（`free` / `ad` / `iap` / `quest`）<br>② 资源账本以服务端为权威，订单幂等接口形状先留好<br>③ 定义「一次广告 = 多少资源」这把尺子，让日后定价能挂到同一把尺上<br>④ 埋点按 `source` 分账，收入能拆出 IAA 与 IAP | 这几项事后改等于重做存档信任模型与全部数值校准，是唯一真正贵的部分。**注意只做接口形状，不接支付 SDK** |
| **可以后加** | 商店 UI、SKU 清单、定价、首充与月卡、支付 SDK 接入、审核资质 | 都是叶子功能，加的时候不动核心循环。版号周期本身是半年到一年以上，现在做实现纯属浪费 |
| **即便开了 IAP 也不做** | 卖英雄或英雄抽卡；直售战力数值；付费墙式难度曲线 | 前两条撞主体验目标——「攒队」的快感来自我选了谁，一旦英雄能买，收集就变成付费进度条。第三条撞《保卫向日葵》的教训：它靠局外装备与钻石强娶变现，代价是零氪打几章就卡关 |

**日后 IAP 优先卖外观。** 主快感是收英雄，外观是收集欲的自然延伸，既不破坏平衡、不制造付费墙，也不与 IAA 的广告位争夺同一份玩家意愿。去广告类商品要谨慎评估：它直接吃掉 IAA 收入，只有在月卡 LTV 明确高于该玩家的广告价值时才成立。

## 5. 设计审视清单（必过）

新增或改动玩法 / 数值 / UI / 商业化前，逐条回答。任一条为「否」且无法修正 → **不做或降权**。

1. **换人有差异**：换掉一个英雄或挪一次站位，是否会明显改变这一波的结果？（不能被数值差完全抹平）
2. **卡关路径**：玩家卡住时，游戏是否把「换阵容 / 调站位 / 换三选一取向」提示为比「再来一局碰运气」更清晰的路径？
3. **胜利归因**：结算是否让人感到「我攒对了」，而不是只感到「这局运气好」？
4. **决策权重**：随机性是否只提供变化，而不是主导胜负？
5. **十秒可懂**：改动后，前 10 秒是否仍能让没玩过的人看懂在干什么？
6. **广告点预算**：核心流程广告点是否仍 ≤ 2？新增曝光是否放在了局外？
7. **变现不成为前置**：变现是否制造「不看广告就过不去」或「不付费就过不去」？若是，违反反目标。涉及 IAP 商品时追加一问：这件商品若上线，是否会让不付费玩家的现有体验变差？会则不做。
8. **观战可读**：自动战斗中，玩家是否还看得清谁在打谁、为什么赢或输？
9. **系统负担**：是否增加了让玩家忘记「攒队」的干扰目标？（多养成、多货币、复杂任务）

## 6. 加 / 慎 / 砍（速查）

| 倾向 | 例子 |
|---|---|
| **加** | 波次预告敌人系别、三选一给出可感取舍、站位收益的即时反馈、结算里点明「靠什么打过的」、下一局的阵容建议 |
| **慎加** | 局外解锁之外的第二条成长线、纯战力数值、只加强度不加选择的英雄、遮挡战场的演出 |
| **砍 / 降权** | 任何让「重开碰运气」比「换搭配」更短的路径；英雄抽卡与付费战力养成（即便日后开 IAP 也不做，见 §4.1）；前置编队流程；核心流程的第三个广告点；插屏 |

## 7. 验收标准（体验是否达标）

| 维度 | 标准 | 测法 |
|---|---|---|
| **体验** | 玩家能说出自己是靠什么打到那一波的 | 试玩后问「刚才是什么让你打到第 12 波」。答案指向选了谁、怎么站即通过；答「运气」或「不知道」即不通过 |
| **商业** | 中位数 IPU ≥ 6，且次留不低于改动前 | 埋点看中位数，同时看「开战 ≥20 场的人里 IPU < 2 的占比」 |
| **买量** | 前 10 秒可懂 | 录前 10 秒给没玩过的人看，问他这游戏在干什么 |
| **节奏** | 卡关点稳定落在第 9–12 波 | 数值原型阶段就要验；太早挫败，太晚则复活广告没需求 |

三条里最可能挂掉的是**体验**那条。它挂了就不是调参能救的，要回到克制强度与三选一的取舍设计。

## 8. 与其他文档的关系

本文件是唯一的体验裁决依据。后续新增的核心玩法循环、数值框架、商业化配置等文档，都是实现本文的手段，不具备更高优先级。数值调参的验收是「换搭配能打得更深，重开碰运气不是最优解」，而不是只看曲线平滑。
